# Запуск импорта

## Быстрый запуск примера

```bash
python process_statements.py
```

С повторной выпиской для проверки дублей:

```bash
python process_statements.py --include-repeat
```

## Обработка своих файлов

```bash
python -m bank_import путь/к/выписке.xlsx \
  --mapping config/projects/atlas.json \
  --output-dir build/import
```

Можно передать несколько файлов разных банков за один запуск. Результат:

- `operations_ready.csv` — готовые уникальные операции;
- `exceptions.csv` — вопросы, по которым нет надёжного правила;
- `duplicates.csv` — повторные операции, не попавшие в готовый журнал;
- `raw_operations.jsonl` — исходные поля для проверки и аудита;
- `control_report.json` — машинная сверка количества и оборотов.

Эти названия используются только во внутреннем каталоге `build`. Пользовательский пример результата находится в `output/sample` с русскими названиями.

## Загрузка в Google Sheets

Установите опциональные зависимости и передайте сервисный аккаунт, которому выдан доступ к таблице:

```bash
pip install -e '.[google]'
python -m bank_import путь/к/выписке.xlsx \
  --mapping config/projects/atlas.json \
  --output-dir build/import \
  --spreadsheet-id SPREADSHEET_ID \
  --credentials data/private/service-account.json
```

Загрузчик читает фактическую строку заголовков `ЖурналОпераций` и раскладывает поля по ней. В видимой части журнала используются поступление, списание, денежный счёт, статьи ДДС/ОПиУ, проект, контрагент, назначение, Дт, Кт и балансовая статья. Служебные поля могут оставаться справа скрытыми для аудита. Правила импорта и учёта в Google Sheets не хранятся: источником истины служит JSON выбранного проекта в репозитории.

## Тесты

```bash
python -m unittest discover -s tests -v
```

Тесты создают миниатюрные книги Т‑Банка, Альфы и Сбера во временном каталоге и не используют реальные реквизиты.
