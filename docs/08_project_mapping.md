# Проектный маппинг

Каждый клиентский проект получает отдельный JSON-файл. Учебный пример находится в `config/projects/training_consulting.json`, чистая заготовка — в `_template.json`.

Правила проверяются сверху вниз. В `when` поддерживаются:

- `direction`: `credit` или `debit`;
- `contains_all`: все фразы должны встретиться в описании, назначении или контрагенте;
- `contains_any`: достаточно одной фразы;
- `not_contains`: запрещённые фразы;
- `counterparty_contains`: фрагмент наименования контрагента.

Блок `set` задаёт статью операции, проект аналитики, раздел и строку ДДС, строку ОПиУ, балансовый счёт и флаги `include_cash_flow`/`include_pnl`.

Денежный счёт определяется по форме источника: Т‑Банк загружается в `Основной счёт`, СберБизнес — в `Резервный счёт`, Альфа‑Банк — в `Дополнительный счёт`. В журнале отдельно хранятся денежный счёт и балансовая статья второй стороны проводки. Поле `Тип операции` остаётся техническим; пользователю достаточно колонок `Поступление`, `Списание`, `Дт` и `Кт`.

Коды справочников не вычисляются из текста платежа. Это стабильные идентификаторы, которые финансист задаёт вручную: `P` используется для иерархии ОПиУ, `C` — для иерархии ДДС, числовой код — для балансового счёта. Наименование можно уточнять без смены кода; смена кода считается изменением модели и проходит ревью.

Если правило не найдено, операция не теряется: она попадает в `exceptions.csv` со статусом `Требует разъяснения`. Изменение маппинга проходит ревью как обычное изменение кода и воспроизводится при повторном запуске.
