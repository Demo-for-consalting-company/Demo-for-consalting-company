# Demo for consulting company

Это закрытый демонстрационный репозиторий: он показывает, как из банковских выписок получить проверенный журнал операций для управленческого учёта. Все организации, реквизиты, документы и суммы вымышлены.

## Самый простой способ попробовать

1. Скачайте три файла из папки [основной сценарий](data/для_загрузки_в_чат/основной_сценарий).
2. Загрузите их в чат вместе с текстом из [готового запроса](prompts/обработать_выписки.md).
3. Ожидаемый результат: 24 операции на входе, 23 распределены автоматически, 1 требует решения, дублей нет.
4. Вопрос возникнет по оплате платформы информационной безопасности. Так и задумано: для неё ещё нет правила.

Чтобы отдельно показать защиту от повторной загрузки, добавьте [четвёртый файл](data/для_загрузки_в_чат/дополнительно/04_ТБанк_повторная_загрузка.xlsx). Тогда система должна найти 8 дублей и не включить их повторно.

## Что происходит с файлами

```text
Выписки трёх банков
        ↓
Чтение банковской формы без переименования исходных полей
        ↓
Единый формат операции
        ↓
Правила именно этого проекта
        ↓
Готовые операции + вопросы по новым случаям + дубли
        ↓
Контроль количества и денежных оборотов
        ↓
Загрузка подтверждённых строк в Google Sheets
```

Парсер отвечает только за чтение формы конкретного банка. После этого общий процесс применяет правила выбранного проекта. Поэтому один и тот же парсер Т‑Банка можно использовать у разных клиентов, а их статьи и проекты не смешиваются.

## Термины без технического жаргона

| Термин | Простое объяснение |
| --- | --- |
| Парсер | Читает Excel-форму конкретного банка и достаёт операции |
| Нормализация | Приводит разные банковские поля к одной понятной структуре |
| Маппинг | Правила, по которым операция получает статью, проект, ДДС, ОПиУ и баланс |
| Pipeline | Вся последовательность от чтения файла до готового результата |
| Raw-слой | Неизменённые исходные поля для проверки и аудита |
| Контрольный отчёт | Сверка строк и денежных оборотов самого импорта |

## Запуск без длинной команды

Из корня репозитория:

```bash
python process_statements.py
```

Команда сама возьмёт три файла основного сценария, применит `atlas.json` и положит подробный технический результат в `build/latest`. Для проверки дублей:

```bash
python process_statements.py --include-repeat
```

## Если появляется новая статья

Система не должна угадывать. Операция попадает в список «Требует решения», а финансист выбирает статью, проект, строку ДДС, строку ОПиУ, балансовую статью и признаки включения в отчёты. После согласования добавляется новое правило в `atlas.json`, обработка запускается повторно, а решение становится воспроизводимым.

Подробный маршрут находится в [документации](docs/README.md). Реальные выписки и ключи доступа нельзя добавлять в Git; для них предназначена игнорируемая папка `data/private/`.
