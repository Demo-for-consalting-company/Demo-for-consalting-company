# Финансовый контур клиента и работа с ИИ-агентом

Этот репозиторий — рабочий шаблон финансовой команды. Он помогает начать проект нового клиента, хранить договорённости, выполнять закрытие периода по единому порядку и передавать клиента другому финансисту. Внутри также сохранён обезличенный учебный пример обработки банковских выписок компании «Атлас».

## Начало работы

1. Открой паспорт и текущее состояние клиента.
2. Проверь реестр источников.
3. Прочитай правила учёта и процесс текущей задачи.
4. Выбери готовое задание для агента.
5. Укажи клиента, период и разрешённые изменения.
6. Получи результат и проверь контрольный отчёт.
7. Прими решения по исключениям.
8. Обнови состояние клиента и историю изменений.

Основные документы: [паспорт клиента](client/01_паспорт_клиента.md), [финансовая модель](client/02_финансовая_модель.md), [текущее состояние](client/05_текущее_состояние.md), [единый рабочий процесс](WORKFLOW.md) и [правила для агента](AGENTS.md).

## Единая модель финансовой работы

```text
Источники
→ финансовые факты
→ правила учёта
→ проверки
→ ОПУ + Баланс + ДДС
→ аналитика и сценарии
→ решение человека
→ обновление правил и планов
```

У клиентов разные банки, таблицы, учётные системы и бизнес-модели. Структура финансовой работы при этом едина: сначала команда подтверждает полноту фактов, затем применяет согласованные правила, выполняет проверки, собирает три связанные формы отчётности и только после этого готовит анализ и варианты решений.

- Google Таблицы содержат финансовые данные и отчётность: журнал операций, проводки, ОПУ, баланс, ДДС, планы и аналитические витрины.
- GitHub содержит знания о клиенте: финансовую модель, правила, проверки, исключения, решения и историю изменений.
- Агент готовит и обрабатывает данные, выполняет сверки, анализирует отклонения и формирует предложения.
- Финансист утверждает методологию, существенные исключения и управленческие решения. Решения собственника фиксируются отдельно от предложений агента.

> Агент не заменяет финансового директора. Он помогает быстрее получать проверяемую финансовую картину, находить отклонения, рассчитывать варианты и готовить вопросы для принятия решений.

## Закрытие начинается с источников

Закрытие периода начинается не с формирования отчёта, а с проверки полноты источников. Для каждого обязательного источника в [реестре источников](registers/sources.csv) должны быть понятны владелец, период, срок получения, контрольная сумма, актуальность и статус.

Статусы источника: `Ожидается`, `Получен`, `Загружен`, `Проверен`, `Есть расхождения`, `Не получен`, `Не используется`.

> Если обязательный источник не получен или не проверен, агент не должен обозначать период как полностью закрытый.

Условия и статусы закрытия описаны в [процессе закрытия месяца](processes/month_close.md).

## Пять рабочих реестров

### Источники

[sources.csv](registers/sources.csv) показывает, какие данные нужны, откуда и когда они поступают, куда загружаются и как подтверждается их полнота. Пустая форма для копирования находится в [source_registry_template.csv](templates/source_registry_template.csv).

### Правила учёта

[accounting_rules.csv](registers/accounting_rules.csv) хранит согласованные способы отражения операций. Допустимые статусы: `Предложено`, `На согласовании`, `Принято`, `Временно`, `Отменено`.

- Агент применяет только принятые или явно разрешённые временные правила.
- Новое правило не создаётся автоматически из одной операции.
- Исправление конкретной строки не всегда означает изменение общего правила.
- Изменение правила содержит дату начала действия и автора решения.
- Правила разных клиентов нельзя смешивать.
- При конфликте применяется более конкретное правило. Если приоритет определить нельзя, операция выносится на решение.

### Проверки

[controls.csv](registers/controls.csv) содержит двенадцать базовых проверок и показывает, блокирует ли ошибка закрытие периода.

> Статус «Проверено» присваивается только при наличии числового или документального результата проверки. Ответ агента «ошибок не найдено» сам по себе не считается проверкой.

### Исключения

[exceptions.csv](registers/exceptions.csv) хранит спорные операции и недостающие данные. Статусы: `Новое`, `Требует данных`, `Требует решения`, `Решено`, `Отложено`, `Закрыто`.

> Исключение должно содержать не только описание проблемы, но и конкретный вопрос человеку.

### Решения

[decisions.csv](registers/decisions.csv) отделяет предложение агента, решение финансиста, решение собственника, выполненное действие и подтверждённый результат. В поле `decision_owner` указывается, кто именно принял решение. Рекомендуемые статусы: `Предложено`, `Решено финансистом`, `Решено собственником`, `В работе`, `Выполнено`, `Результат проверен`.

> Предложение агента не является принятым решением. Ожидаемый эффект не является фактическим результатом.

## Что хранится в GitHub

- правила клиента;
- описание процессов;
- шаблоны;
- обезличенные примеры;
- задания агентам;
- проверки;
- история решений без чувствительных данных;
- код автоматизаций при его наличии.

## Что хранится в Google Таблицах

- журнал операций;
- управленческие проводки;
- ОПУ;
- баланс;
- ДДС;
- планы;
- аналитические витрины;
- рабочие контрольные показатели.

## Что не хранится в GitHub

- реальные банковские выписки;
- пароли;
- токены;
- ключи сервисных аккаунтов;
- персональные данные;
- конфиденциальные договоры;
- выгрузки с чувствительной информацией.

В репозитории допускаются только обезличенные примеры.

## Как подключить нового клиента

1. Создайте отдельный закрытый репозиторий из этого шаблона.
2. Заполните документы в [client](client), начиная с паспорта и финансовой модели.
3. Заполните [реестр источников](registers/sources.csv) и согласуйте обязательные источники.
4. Зафиксируйте статьи и правила в [плане счетов и статей](client/03_план_счетов_и_статей.md) и [реестре правил](registers/accounting_rules.csv).
5. Назначьте владельцев источников, проверок и решений.
6. Выберите нужный процесс и готовое задание агенту.
7. Проведите пробное закрытие, зафиксируйте исключения и только после проверок утвердите рабочий порядок.

До начала регулярной работы владелец финансовой функции должен утвердить: границы управленческого учёта, правила признания и распределения, существенность, обязательные источники и проверки, права на изменение данных, состав отчётности и порядок закрытия.

## Если вы замещаете другого финансиста

1. Прочитайте [текущее состояние](client/05_текущее_состояние.md).
2. Проверьте незакрытые исключения.
3. Проверьте ожидаемые решения и сроки.
4. Убедитесь в наличии необходимых доступов.
5. Запустите проверку полноты источников.
6. Не меняйте методологию до изучения принятых правил.

Для полной передачи используйте [готовое задание агенту](prompts/handover_client.md) и [шаблон передачи](templates/handover_template.md).

## Как создать организацию и скопировать шаблон

Репозиторий опубликован как GitHub Template. Для новой компании создайте организацию, пригласите сотрудников и сделайте отдельную закрытую копию через `Use this template`. Пошаговый порядок со снимками экрана находится в [PDF-инструкции по созданию организации](output/pdf/Как_создать_организацию_GitHub_и_скопировать_проект.pdf).

Рабочую копию с реальными данными клиента создавайте только с видимостью `Private`. Публичным остаётся обезличенный исходный шаблон.

## Сохранённый учебный пример

Учебный сценарий показывает, как из трёх обезличенных банковских выписок компании «Атлас» получить проверенный журнал операций.

1. Возьмите три исходные выписки: [Т-Банк](data/sample/основной_сценарий/01_ТБанк_август.xlsx), [Альфа-Банк](data/sample/основной_сценарий/02_АльфаБанк_август.xlsx) и [СберБизнес](data/sample/основной_сценарий/03_СберБизнес_август_новая_статья.xlsx).
2. Откройте [учебный пример в Google Таблицах](https://docs.google.com/spreadsheets/d/1116aAKX8rnDXxYKIA0akJJtDpxi7U9Jju2YB2Xxh1nA/edit?gid=2026091401#gid=2026091401) — это основной онлайн-пример для сотрудников.
3. Если нужна автономная копия, используйте [учебную Excel-книгу](output/sample/Учебная_финансовая_таблица.xlsx) с той же логикой проверки результата, открытой операции и денежной сверки.
4. Используйте [готовое задание на обработку выписок](prompts/обработать_выписки.md).
5. Сравните итог с [сохранёнными CSV](output/sample), учебной таблицей и [контрольным отчётом](output/sample/контроль.md).
6. Для проверки повторной загрузки добавьте [четвёртый файл](data/sample/дополнительно/04_ТБанк_повторная_загрузка.xlsx).

В основном сценарии 24 операции: 23 получают статью автоматически, одна становится вопросом финансисту, дублей нет. Правила «Атласа» находятся в [atlas.json](config/projects/atlas.json), объяснение — в [учебной документации](docs/README.md). Техническая часть сохранена в `bank_import`, но для обычной финансовой работы её открывать не требуется.
